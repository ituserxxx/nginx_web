## 新增：SSL 证书上传（解压 + 按域名归置 + 回填路径）

需求：证书除手填路径外还要能上传，后端判断后缀自行解压，按域名放到对应目录，
并把位置填进 nginx 配置。

### 后端 `server/main.go`（新增约 240 行）

- 新增导入 `archive/tar`、`archive/zip`、`compress/gzip`、`bytes`（`io`/`os`/`filepath` 已有）。
  注：`mime/multipart` 加了但没直接用（FormFile 返回值类型），被 go vet 拦下后已移除。
- 纯函数：`certDirName`（安全化）→ `certDirFor` → `safeJoin`（zip-slip）→
  `extractCertArchive`（按后缀分派 zip / tar.gz / tgz / tar / 单文件）→
  `classifyPEM` + `pickCertAndKey`（按内容识别）→ `listCertFiles`。
- 新接口 `POST /api/nginx/sites/cert`：`ParseMultipartForm(32MB)`，字段 `domain` + `file`；
  校验域名合法 → `RemoveAll` 旧目录 → 解压 → 识别 → 返回
  `{ok, dir, cert, key, files}`。**不隐式写 nginx 配置**，由前端回填后用户点保存。

### 两个踩坑（已写进 MEMORY.md）

1. **zip-slip 判定不能用 `filepath.IsAbs`**：Windows 下 `\tmp\x` 的 IsAbs 语义导致漏判，
   tar 里 `/tmp/evil.crt` 竟然解压成功。改为先按斜杠判 `HasPrefix("/")` 与盘符
   （`x[1]==':'`），再 Clean 后判 `..`，最后用 `filepath.Abs` 前缀兜底。
2. **`certDirName` 顺序**：先转义分隔符再取 Base，所以 `../escape` 会变成 `.._escape`
   （安全但名字怪）。补了 `TrimLeft(name, ".")` 变成 `_escape`。

### 前端 `web/src/App.vue`

- HTTPS 区块加 `certMode`（upload / manual）`a-radio-group` 切换；
  upload 模式用 `a-upload-dragger` + `customRequest`（必须带 domain，故不能用默认提交）
  + `beforeCertUpload`（限 32MB）；上传成功后回填 cert/key，并展示解压目录与文件清单 tag。
- `customUpload` **返回 Promise**（原本没返回，导致测试 await 提前结束、断言取到旧值）。
- 新增状态 `certUploading` / `certDir` / `certFiles`，`openAddSite` / `openEditSite` 都重置。
- `package.json` 显式声明 `@ant-design/icons-vue@^7.0.1`（原为 ant-design-vue 的传递依赖，
  现已在 node_modules 中，声明后依赖链更明确）。

## 新增：单文件构建（前后端打包成一个二进制 + 压缩）

需求：写 build 脚本，把前后端全部打包成一个二进制可执行文件，再压缩。

### 实现
- 新增 `server/embed.go`（`//go:build embed`）：`//go:embed dist` → `webrootFS embed.FS` +
  `const embedWebroot = true`。
- 新增 `server/noembed.go`（`//go:build !embed`）：`var webrootFS fs.FS`（空）+
  `const embedWebroot = false`。**不带 embed 标签时（start.sh 开发模式、go test）不内嵌前端，
  后端只暴露 /api，行为不变**；这是刻意设计，避免 test 强依赖构建产物。
- `server/main.go` 新增 `registerWebroot(mux)`：仅当 `embedWebroot` 为真时注册兜底路由 `/`。
  非 `/api` 路径：资源存在则走 `http.FileServer`（正确 Content-Type）；不存在则直接
  `fs.ReadFile(sub,"index.html")` 写出 `text/html`（**不能改写为 `/index.html` 交给
  FileServer**——它会把 /index.html 301 重定向到 /，导致不跟随重定向的客户端拿到空响应）。
- 新增 `build.sh`（WSL/Linux 专用，拒绝 Windows Git Bash）：检查工具链 →
  `npm run build`（必要时重装 Linux 原生 node_modules，因 vite8 rolldown binding） →
  复制 `web/dist` → `server/dist` → `go build -tags embed -ldflags "-s -w" -o nginx-web .` →
  清理 `server/dist` → 压缩（`upx --best --lzma` 原地优先；无 upx 则 `gzip -9 -k` 生成
  `nginx-web.gz`）。
- `.gitignore` 增 `/server/dist/`、`/nginx-web`、`/nginx-web.upx`、`/nginx-web.gz`。
- README「部署」章节新增「单文件构建」小节。

### 验证
- 后端 `go test` 全过（39 个，无回归）；gofmt / vet OK。
- 用最小 `server/dist`（仅 index.html + assets/app.js）在 Windows 上 `go build -tags embed`
  实测运行：`GET /` 200 text/html、`/spa/route` 200（SPA 回退，非 301）、`/assets/app.js` 200
  text/javascript、`/api/hello` 200 JSON、`/api/nope` 404 —— 全部符合预期。
- 注：本机 sandbox 禁用了 wsl.exe，无法跑 `build.sh` 全流程；脚本的 WSL 路径按既定约定编写，
  且其 embed 机制已用上述 Windows 实测证明正确。

## 登录鉴权（gating 安装/配置页）

### 需求
写登录页，登录后才能进安装与配置页；密码读 `.env` 的 `APP_PASSWORD`，默认 `admin`。

### 后端改动（server/main.go）
- 新增 `appPassword`（默认 "admin"）、`initPassword()`：优先级 环境变量 APP_PASSWORD > .env 的 APP_PASSWORD > admin。
- `.env` 解析：`parseDotEnv(data)`（忽略 # 与空行、首个 = 切分、去单/双引号）+ `loadDotEnv()` 读工作目录 `.env`。
- 会话：`sessions map[token]time.Time` + `sessionMu`；`requireAuth` 中间件仅放行公开接口
  （/api/hello、/api/login、/api/me、/api/logout），其余 `/api/nginx*` 未带有效
  HttpOnly Cookie 返回 401。`subtle.ConstantTimeCompare` 比对密码。
- 新增 handler：`POST /api/login`（下发 Cookie）、`GET /api/me`（返回 {authenticated}）、
  `POST /api/logout`（销毁会话）。
- main 中先 `initPassword()`，再 `logging(requireAuth(mux))`；SPA 静态页（/）不拦截，
  由前端按 /api/me 决定登录页。

### 前端改动（web/src/App.vue）
- 新增 `loggedIn`/`loginForm`/`loginError`/`loginLoading`；`onMounted(checkAuth)` 取代原直接加载。
- `checkAuth()` 查 /api/me → 已登录则 `afterLoginLoad()`（原 onMounted 逻辑）；`login()`/`logout()`。
- 未登录显示登录卡片（LockOutlined + 密码框 + 登录按钮 + 错误 Alert），已登录显示主应用；
  头部加「退出登录」按钮。`detect`/`loadSites` 接入 `handleUnauthorized(res)`（401 退回登录页）。
- 同源（单文件部署 / Vite 代理）下 fetch 默认带 Cookie，无需额外 credentials；登录/登出/me 显式
  加 `credentials:'same-origin'`。
